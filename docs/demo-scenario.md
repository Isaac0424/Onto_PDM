# Onto PDM 시연 시나리오

- 길이: 약 15분 (핵심만 보면 8분). 준비 5분 별도
- 한 줄 소개: **CAD 파일 하나를 올리면, 부품 모양에서 볼트 종류를 읽고, 회사 품번(OPMS)과 맞춰 보고, 그 부품에 적용되는 조립 규칙까지 3D 위에 띄워 준다.**
- 쓰는 CAD: `Body HCR12A R00 3D.stp` (한화 협동로봇 HCR-12A 본체, 9.3 MB, 부품 103개 · 26종 · 제조 24단계)
- 이 문서의 숫자는 2026-11-12 이 PC에서 직접 본 값이다. **OPMS에는 지금 시험용 부품이 3개(육각볼트 2 · 육각플랜지볼트 1)뿐이라 소켓 볼트의 보유 품번 후보는 나오지 않는다.** OPMS에 소켓 볼트 품번이 등록돼 있으면 3-2의 "후보 N개"가 나온다. 시연 전에 한 번 돌려 보고 다르면 고친다.
- 이 시나리오를 그대로 녹화한 영상: `docs/demo/onto-pdm-demo.mp4` (약 2분 18초).

## 0. 시연 전에 (준비)

| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | **OPMS를 먼저 켠다** (Neo4j가 응답해야 한다) | OPMS 쪽 안내대로 |
| 2 | 저장소 루트에서 `node tools/dev-pdm.mjs` | 파일 서버 8788 · 백엔드 8100 · 웹 5173이 뜬다 |
| 3 | `http://localhost:5173` 열기 | 오른쪽 위 줄: **"OPMS 연결됨 · 온톨로지 0.20.0 · 부품 3개"** (OPMS 데이터에 따라 숫자는 다르다) |
| 4 | CAD 열려 있는지 | 이미 서버 DB에 있으면 자동으로 열린다. 없으면 "CAD 올리기"로 올리고 첫 분석을 끝내 둔다 (큰 파일이라 처음엔 수십 초) |
| 5 | 브라우저 창 크기 1500×900 이상, 확대 100% | 오른쪽 패널이 잘리지 않는다 |

- 전에 한 번 열어 두면 **서버 DB에 저장돼 있고 10분 동안 브라우저 캐시에 남아** 다시 열어도 바로 뜬다. 시연 직전에 한 번 열어 두면 안전하다.
- **연결 상태가 "연결 안 됨"이면** 시연을 시작하지 않는다. OPMS를 확인하고 다시 켠다 (화면은 열리지만 품번 후보가 안 나온다).

## 1. 도입: 무엇을 해결하나 (1분) — 화면 없이 말로

- 설계 CAD에는 부품 이름만 있고 **우리 회사 품번이 없다.** 사람이 부품마다 품번 마스터(OPMS)에서 찾아야 한다.
- 어떤 부품이 어디에 어떤 토크로 조립되는지도 매뉴얼을 뒤져야 한다.
- Onto PDM은 이 둘을 CAD에서 바로 이어 준다. **품번과 분류(온톨로지)는 OPMS가 소유하고, PDM은 읽기만 한다.**

## 2. CAD 열기와 구조 보기 (2분) — 메인 화면 `/`

1. 메인 화면이 열리면 **3D 분해도**가 바로 보인다. 위쪽 `> 등록한 CAD 1 · 열린 CAD · Body HCR12A R00 3D.stp` 줄은 접혀 있다.
   - 말하기: "올린 CAD는 서버 DB에 저장돼 있고, 한 번 연 CAD는 창을 닫아도 10분 동안 바로 열려요."
   - 줄을 눌러 펴서 카드(`STP · 9.3 MB · 부품 103개 · 24단계`, `서버 DB 저장됨`)를 보여 주고 다시 접는다.
2. 오른쪽 **제조 순서**: "CAD 구조에서 나눈 24단계 · 부품 26종". 단계마다 부품과 개수가 나온다.
   - 보여 주기: 3단계 `HCR12A_J1_HOUSING_COVER_R1`, 4단계 `BOLT-M4 ×16`.
3. 3D를 마우스로 돌리고(왼쪽 드래그), 휠로 확대한다. 단계를 누르면 그 단계의 부품이 **홀로그램 3D에서 분해**된다.
   - 다른 화면(조립 규칙 등)에 갔다 와도 CAD를 **다시 불러오지 않는다.** 이것도 한 번 보여 주면 좋다.

## 3. 볼트 한 개를 따라가기 — 핵심 (6분)

`BOLT-M4`(4단계, ×16)를 누른다.

### 3-1. 모양을 보고 볼트 종류 판단
- 오른쪽 아래 **속성 탭**을 연다. 위쪽 **"형상으로 본 볼트 종류"** 블록: 머리 모양, 윗면 구멍, 나사 지름과 길이를 읽어 **종류 후보를 점수와 근거**로 보여 준다.
- 말하기: "부품 이름을 읽는 게 아니라 **메시(삼각형 모양) 자체를 분석**했어요. 이름이 `BOLT`가 아니어도 모양으로 판단해요."
- 보여 주기: 후보 이름(예: 육각구멍붙이볼트), 근거 줄(머리 윤곽, 구동부 구멍), `M4`와 추정 길이.
- 구멍이 안 보이는 단순화 모델이면 **하나로 단정하지 않고 후보 여럿**을 낸다. 이것도 의도한 동작이다 (틀린 확신을 만들지 않는다).

### 3-2. 품번 후보 매칭
- OPMS에 같은 규격 품번이 있으면 `BOLT-M4` 행 칩이 **"후보 N개 · 추정"**으로 바뀌고 누르면 OPMS의 실제 부품 후보가 나온다. **지금 OPMS(부품 3개)에는 없어서 "미보유 · 추정 규격"으로 나온다** — 이 경우 "회사에 같은 규격이 없다 → 등록 대상"이라고 설명한다.
- 말하기: "확정하기 전에도 **모양에서 나온 규격(M4 · 15 mm 등)으로 OPMS를 자동 조회**해요. 다만 **추정이라서 자동 확정은 없고, 사람이 고르면 보유 품번이 돼요.**"
- 후보 한 줄: `확인한 K개 속성이 모두 일치 · 미확인 …` — 길이처럼 못 읽은 값은 **일치로 치지 않고 "미확인"으로 따로** 보여 준다.
- 후보 하나를 확정하면 칩이 `P-000…` 품번으로 바뀌고 **"보유 · 1"** 숫자가 올라간다.
- 같은 규격 볼트는 묶어서 요청한다 (12A 전체에서 OPMS 요청은 5개).

### 3-3. 온톨로지 연결
- 위 탭 중 **온톨로지**를 연다. 확정한 부품이면 **분류 경로(기계 부품 › 체결 부품 › 볼트 › 육각구멍붙이볼트)와 재질 · 표면처리**가 그래프로 이어진다.
- 말하기: "이 분류와 값은 **OPMS가 관리하는 온톨로지**예요. PDM은 읽기만 해서 마스터가 하나로 유지돼요."

### 3-3b. OPMS 필수 속성 체크리스트
- 속성 탭 아래 **"OPMS 필수 속성 · 확인 K/N"**: 이 분류를 등록하려면 어떤 속성이 필요한지 `확정 / 추정 / OPMS가 채워요 / 미확인`으로 보여 준다. 값이 OPMS 허용 범위를 벗어나면 **호박색**으로 알린다.
- 말하기: "재질이나 강도 등급은 **CAD로는 알 수 없어서** 미확인으로 남아요. 지어내지 않아요."

## 4. 조립 규칙이 3D 위에 뜨는 것 (2분)

1. 볼트(또는 규칙이 있는 부품)를 고르면 **3D 위 카드와 아래 자막**에 적용되는 조립 규칙이 뜬다.
2. 볼트 종류를 확정하고 **역할(예: 로봇 베이스 고정 볼트)을 고르면** 규칙이 정해진다. 로봇 모델이 파일 이름에서 `HCR-12A`로 읽히면 **모델별 표에서 한 줄**(M12 × 25, **140 N·m**)로 좁혀진다.
   - 출처 표시: `사용설명서(KR) 3.3절 p.49`. 사용설명서에 있는 값은 확정으로 보이고, 없는 값은 **"작성 필요"** 로 보인다.
3. 말하기: "**값을 지어내지 않아요.** 근거가 없으면 비워 두고 '작성 필요'라고 말해요."
4. 종류를 알 수 없는 부품(판, 커버)은 "종류를 알 수 없어 규칙을 고를 수 없어요. 볼트는 형상으로 종류를 확정하면 규칙이 떠요"라고 안내한다. 오류가 아니라 상태라서 빨강이 아니다.

## 5. 규칙집과 작업 표준 (2분)

- **조립 규칙 `/rules`**: 위쪽 상태줄 "규칙집 적재됨 · 규칙 23 · 작업표준 10 · 공백 19 · **모두 초안(검토 전)**". 규칙마다 **값의 출처 배지**(사용설명서 쪽 번호 · CAD 추정 · 작성 필요 G-xxx)를 보여 준다. 공백 19개가 지금 사람이 채워야 할 일 목록이다.
- **작업 표준 `/mes`**: 설치 · 점검 작업표준서 10건(목적 · 공구 · 작업 순서 · 점검 항목). 근거가 없는 표준 시간은 **"표준 시간 없음 — 근거 없음"** 으로 나온다. 인쇄하면 현장용 서식으로 나온다.
- 말하기: "초안이고 **사람이 검토해야 확정돼요.** 어디가 비었는지가 바로 보여서 보강 우선순위를 정하기 쉬워요."

## 6. 마무리 (1분)

- 정리: CAD → **모양으로 볼트 종류** → **OPMS 품번 후보** → **온톨로지 연결** → **조립 규칙 · 작업 표준**.
- 앞으로: OPMS가 요청한 **머리 모양(`headType`)과 버튼 · 접시 머리 볼트 분류가 온톨로지 0.20.0에 들어왔다.** PDM은 이 분류를 "제안(미등록)"이 아니라 정식 분류로 보여 준다.

## 시연에서 말하면 안 되는 것 · 솔직하게 말해야 하는 것

| 주제 | 사실 |
|---|---|
| 지원 범위 | **볼트만** 형상으로 종류를 판단한다. 판, 커버, 하우징은 "규격 확정 필요"로 남는다 (보이는 화면에 이 칩이 많이 보인다: 보유 0 · 후보 4 · 미보유 1 · 규격 확정 대기 21) |
| 검증 범위 | 실제 STEP 4개에서 볼트로 판정한 119개를 **모두 소켓 헤드로 맞혔다.** 실제 파일의 볼트가 전부 소켓 헤드라서 **육각, 플랜지, 버튼, 접시는 시험용 모양으로만 확인**했다 |
| 임시인 부분 | OPMS에 `headType`이 아직 없어 **백엔드가 분류 이름으로 임시 대응**한다. 매칭 점수도 OPMS 방식을 옮겨 적은 **임시 구현**이다 |
| 자동 확정 | **없다.** 추정은 "후보 · 추정"일 뿐이고 사람이 확정해야 한다 |
| 규칙 내용 | 모두 **초안 · 검토 전**이다. 확정 값은 사용설명서 근거(베이스 고정 토크 30 · 45 · 140 N·m, 점검 8항목 등)뿐이고 M3 · M4 소켓 토크, 표준 시간, 조립 순서는 **작성 필요**다 |
| 등록 요청 | 새 부품 요청은 **복사해 쓰는 초안**까지다. OPMS로 보내는 기능은 없다 |
| 단위 | OBJ · STL 같은 단위 없는 파일은 mm로 가정해서 추정이 틀릴 수 있다 (그래서 확정이 아닌 후보) |

## 예상 질문

| 질문 | 답 |
|---|---|
| 온톨로지는 어디에 저장되나? | OPMS가 소유한다. PDM은 같은 Neo4j를 **읽기 전용으로만** 읽는다 (코드로 쓰기를 막아 두었다) |
| 조립 규칙도 온톨로지에 들어가나? | 지금은 PDM 저장소의 YAML(`rules/`)이고, 분류 코드로 OPMS 분류와 연결된다. 그래프(PDM 전용 라벨)에 올리는 안을 검토 중이다 |
| CAD 파일은 어디에 저장되나? | 서버 DB(SQLite)가 정본이고, 브라우저는 마지막 사용 후 10분 캐시다 |
| 틀리면? | 후보가 틀려도 사람이 고르기 전에는 확정되지 않는다. 값이 없으면 단정하지 않고 "미확인"이라고 말한다 |
| 다른 CAD 형식은? | STEP 외에 OBJ, STL, GLB도 열린다. 정확한 부품 구조와 단위는 STEP이 가장 좋다 |

## 장애가 났을 때

| 증상 | 대응 |
|---|---|
| "OPMS 연결 안 됨" | OPMS가 안 켜졌다. OPMS를 켜고 상태줄의 다시 시도를 누른다. 안 되면 CAD 보기와 형상 분석만 보여 주고 매칭은 말로 설명 |
| 후보가 안 나온다 | 볼트가 아닌 부품이거나 규격 추정 전이다. 볼트(`BOLT-M4` 등)를 다시 고르고 몇 초 기다린다 |
| 3D가 느리다 | 첫 분석(9 MB)이 끝날 때까지 기다린다. 시연 전에 한 번 열어 두면 캐시에서 바로 열린다 |
| 화면이 이상하다 | 새로고침(F5). 올린 CAD는 서버 DB에 있어서 사라지지 않는다 |

## 시연 전 리허설 체크리스트

- [ ] 상태줄이 "OPMS 연결됨 · 온톨로지 0.20.0"이다
- [ ] `BOLT-M4`를 누르면 형상 분석 후 "후보 N개 · 추정" 또는 "미보유 · 추정 규격"이 나온다 (OPMS 데이터에 따라)
- [ ] 후보 하나 확정 → 품번 칩 → 온톨로지 그래프에 분류 경로가 뜬다 (확정한 값은 CAD별로 기억되니, 같은 CAD로 다시 시연할 때는 이미 확정된 상태에서 시작한다. 처음부터 보이려면 확정 전에 시연하거나 다른 부품으로 한다)
- [ ] 규칙 카드에 사용설명서 쪽 번호가 보인다 (역할 선택 위치를 외워 둔다)
- [ ] `/rules`, `/mes`에 다녀온 뒤 CAD가 다시 로드되지 않는다
- [ ] 빨간색이 보이는 곳이 없다 (빨강은 진짜 오류에만 쓴다)
