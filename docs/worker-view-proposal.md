# 작업자용 화면 제안 (영향 분석)

상태: **제안만 있다. 구현하지 않았고 PRD도 고치지 않았다.** 작성 2026-11-11.
배경: 사용자가 "Onto PDM은 제조공정을 하는 사람(조립 작업자)이 조립할 때 보는 CAD 화면 느낌으로 가야 한다"고 정했다.
쓰는 말: 개발 용어를 줄였다. 꼭 필요한 말은 처음 나올 때 풀어 썼다.

## 0. 한 줄 결론

- **무게중심이 바뀐다. 다만 관리 기능을 버리는 것은 아니다.** 지금 PRD는 "엔지니어가 CAD를 올리고 관리하는 프로그램"이 중심이고 작업자는 "시안만 나오는 먼 사용자"(3장)다. 이제는 **작업자가 매일 보는 화면이 중심**이 되고, 엔지니어 기능은 그 화면에 보일 내용을 **만들고 확정하는 쪽**으로 역할이 바뀐다.
- **작업자 화면은 "조회 전용"이 맞다고 본다.** 작업자는 보기만 하고 설정 · 등록 · 승인은 하지 않는다. 단, 현장에서는 "확인했다" 표시나 담당자 호출처럼 **기록만 남기는 동작**이 필요할 수 있어서 이것을 허용할지는 사용자가 정해야 한다(4장 질문 6).
- **제일 중요한 설계 원칙: 작업자는 "확정된 것"만 본다.** 지금 CAD 스튜디오는 파일을 올리면 그 자리에서 분석해 보여 준다(추정이 섞인다). 작업자에게는 엔지니어가 확인하고 확정해서 내보낸 **작업표준**(지금의 MES 화면이 만드는 묶음)을 읽게 해야 한다. 작업자가 추정을 보고 일하면 안 되기 때문이다.
- 판정과 품번은 작업자 화면에서도 **OPMS 값만** 쓴다(3장에서 확인).

## 1. 작업자 화면에 무엇이 어떻게 보여야 하나 (제안)

원칙: **한 번에 한 단계만.** 글씨는 크게, 장갑을 껴도 누를 수 있는 큰 버튼, 색에만 의존하지 않고 글자와 모양도 함께(색을 잘 못 보는 사람 · 밝은 작업장 대비).

| 화면 요소 | 작업자에게 보이는 모습 |
|---|---|
| **지금 할 일** | 맨 위에 크게: "단계 3 / 9 — 상부 커버 닫기". 그 아래 이번 단계 부품 이름, **품번(OPMS에서 읽은 값)**, 필요한 개수("4개") |
| **3D 화면** | 이번 단계 부품만 밝게 강조하고 나머지는 흐리게. 들어가는 방향을 화살표로. 이미 있는 분해 · 조립 모션을 "이번 단계만" 반복 재생. 단계 이동은 "이전 / 다음" 큰 버튼 |
| **필요한 공구 · 조이는 힘 · 주의사항** | 큰 글씨 카드. **안전에 관한 주의가 맨 위**, 그다음 공구, 그다음 조이는 힘(토크) 값. 값은 "0.6 N·m ±10%"처럼 숫자와 단위를 크게 |
| **맞는지 확인 결과** (OPMS의 적합성 판정) | 네 가지를 색 + 아이콘 + 글자로 구분(아래 표). 한 줄 이유를 쉬운 말로: "볼트 16 mm. 18 mm 이상이어야 합니다 (2 mm 부족)" |
| **추정값 주의** | 판정에 쓴 치수가 CAD에서 **추정한 값**이면 판정 옆에 눈에 띄는 **"추정"** 표시(점선 테두리 + 글자) + "도면 치수로 잰 추정입니다. 실물로 확인하세요". 추정이면 OPMS가 판정을 "조건부 · 알 수 없음"으로 낮춰서 주므로 **추정이 있는 단계는 거의 항상 이 표시가 뜬다**(0장의 "확정된 것만 본다"가 중요한 이유) |
| **대신 쓸 수 있는 부품** | **작업자가 스스로 바꾸지 않는다.** "대신 쓸 수 있는 부품이 있습니다. 담당자 확인 후 사용" 정도로만 안내하고 부품 이름 · 품번을 보여 준다. 이 기능은 OPMS의 대체 판정(후속 단계)이 생겨야 가능하므로 **지금은 자리만 잡아 둔다** |

### 판정 네 가지를 작업자에게 어떻게 보여 줄까 (제안, 문구는 현장과 정해야 함)

| OPMS 판정 | 작업자에게 보이는 이름 | 색 · 모양 | 작업자가 할 일 |
|---|---|---|---|
| 통과 | **맞음** | 초록 · 체크 | 그대로 진행 |
| 조건부 | **확인 필요** | 노랑 · 느낌표 | 이유를 읽고 **실물을 확인**한 뒤 진행. 확인했다는 표시를 요구할지는 질문 6 |
| 실패 | **멈춤** | 빨강 · 정지 표시 | **작업을 멈춘다.** 다음 단계 버튼이 **잠긴다**. 화면에 이유(몇 mm 부족한지)와 "담당자 호출" 버튼. 담당자가 해제하기 전에는 진행하지 않는다 |
| 알 수 없음 | **확인 못 함** | 회색 · 물음표 | 시스템이 판단하지 못했다는 뜻이다. "맞다"로 읽으면 안 된다. 담당자에게 확인 요청(진행을 막을지 허용할지는 질문 2) |

- "실패일 때 진행을 막는다 / 경고만 한다 / 누가 풀 수 있다"는 **안전 · 품질 정책**이라 시스템이 임의로 정하면 안 된다. 위 표는 **가장 안전한 쪽의 시작안**이다. 사용자와 현장이 정해야 한다.
- OPMS가 주는 이유 문장을 그대로 보일지, 작업자용 쉬운 문장으로 바꿀지는 정해야 한다. **바꾸는 일은 "표시 문구 번역"까지만** 하고 판정을 바꾸지 않는다(3장).

## 2. 지금 만든 것을 어떻게 나눌까

의견: 같은 프로그램 안에 **"작업 모드"(작업자, 조회 전용)** 를 새로 만들고, 지금의 CAD 스튜디오는 **"엔지니어 모드"** 로 둔다. 3D와 안내 카드 같은 부품(코드)은 같이 쓰고, 화면과 권한만 나눈다. 별도 프로그램을 새로 만드는 것보다 훨씬 적게 든다.

| 지금 있는 것 | 작업자용 | 구분 | 이유 |
|---|---|---|---|
| **CAD 스튜디오의 3D · 단계 이동 · 자동 재생** | ✅ **그대로 쓴다** | 작업 모드에 재사용 | 작업자 화면의 중심이다. 글씨 크기 · 버튼 크기만 키운다. 이미 있는 "조립 순서 나누기"와 "방향 표시"가 그대로 쓰인다 |
| **조립 안내 카드 + 자막(HUD)** | ✅ **그대로 쓴다** (모양만 다듬음) | 작업 모드에 재사용 | 공구 · 토크 · 주의사항이 이미 있다. 글씨를 키우고 안전 주의를 위로 올리고 **판정 줄을 추가**한다 |
| CAD 파일 올리기 · 속성 추출 · 확정 화면 | ❌ | **엔지니어용** | 설정 · 확정 일이다. 작업자 화면에는 안 보이게 한다 |
| 부품 매칭 확인 · 보유 품번 연결 | ❌ | **엔지니어용** | 확정하는 일이다. 작업자는 확정된 결과(품번)만 본다 |
| OPMS 등록 요청 · 내 등록 요청 | ❌ | **엔지니어용** | 등록은 엔지니어가 한다 |
| 온톨로지 보기(부품의 분류 · 재료 · 속성 그래프) | ❌ | **줄이거나 미룬다** | 작업자에게는 어렵고 필요 없다. 엔지니어용으로 남긴다 |
| 제품 연결 그래프(3D) | ❌ | **엔지니어용, 작업자에게는 미룬다** | 제품 전체 구조를 보는 용도다. 작업자는 "지금 단계"가 중요하다 |
| 조립 규칙 화면(목록 · 상세) | ❌ | **엔지니어용** | 규칙을 읽고 점검하는 화면이다. 작업자는 카드 안의 규칙 번호만 작게 본다 |
| BOM 가져오기 | ❌ | **엔지니어용** | 설계 자료 입력이다 |
| **MES 발행 · 작업표준 묶음** | 📌 **작업자 화면의 재료** | 엔지니어용(만드는 쪽) | 작업자가 보는 "확정된 단계 · 부품 · 값 · 주의 · 공구"가 여기서 나온다. **작업 모드는 이 확정본을 읽는다.** 지금은 파일 내려받기 수준이라 "작업 모드가 읽을 수 있는 확정본" 단계가 새로 필요하다 |
| 품목 · 문서 · 관리자 화면 | ❌ | **엔지니어 · 관리자용** | 그대로 |

### 작업자는 조회 전용이 맞나?

**맞다고 본다.** 이유는 세 가지다.
1. 작업자가 설정이나 등록을 바꿀 수 있으면, 현장에서 의도치 않게 확정된 내용이 바뀐다.
2. 지금 권한 체계에 이미 **조회 전용 역할(viewer)** 이 있어 "작업자 = 조회 전용"으로 맞추기 쉽다. 작업자 전용 역할 `worker`를 따로 두는 쪽이 이름이 분명하다(구현 때 정한다).
3. 판정이 "멈춤"일 때 작업자가 혼자 풀 수 있으면 판정의 의미가 없어진다.

**단 하나의 고민**: "확인했다" 표시, 단계 완료 기록, 담당자 호출은 설정이 아니라 **현장 기록**이다. 이것까지 막으면 쓸모가 줄 수 있다. 허용할지는 질문 6.

### 3.2 fit-check-plan.md · OPMS 연동에 미치는 영향

- **판정을 언제 받아 오나**(새 결정이 필요): 작업자가 단계를 넘길 때마다 OPMS를 부르면 느리고 OPMS가 멈추면 현장이 멈춘다. 두 가지 안이 있다.
  - (가) **발행할 때 판정을 미리 받아 확정본에 같이 묶는다(스냅샷).** 작업자 화면은 OPMS를 부르지 않고 확정본만 읽는다. 오프라인에 유리하고 빠르다. 대신 OPMS 규칙이 나중에 바뀌어도 이미 발행된 판정은 옛 것이다(`ontology_version`을 같이 보여 주고, 규칙이 바뀌면 재발행한다).
  - (나) 단계마다 실시간 호출. 항상 최신이지만 현장이 네트워크와 OPMS에 묶인다.
  - **제안은 (가)**. 이유: 작업자는 "확정된 것"만 본다는 원칙과 맞다. 다만 OPMS 쪽 계약 · 규칙이 바뀔 때의 재발행 절차가 필요하다.
- **단말이 OPMS를 직접 부르지 않는다.** OPMS에는 인증이 없고 127.0.0.1(자기 컴퓨터)에서만 부르도록 되어 있다(`backend-plan.md`). 현장 단말은 **PDM 서버만** 부른다.
- **추정 표시가 많이 뜬다.** 홈 깊이를 CAD에서 추정하므로(`fit-check-plan.md` 3장) 작업자 화면에서 "추정" 표시가 자주 나온다. 현장에서 실물을 재서 넣는 기능은 "조회 전용"과 부딪히므로 질문 8.
- **표시 문구 변환**: OPMS의 이유 코드(`shortfall` 등)를 쉬운 말로 바꾸는 일은 "번역"이다. **판정 결과를 PDM이 바꾸거나 다시 계산하지 않는다.** OPMS가 작업자용 쉬운 문장도 같이 내줄 수 있으면 더 좋다(OPMS와 협의).
- 대체 부품 안내는 OPMS 대체 판정(후속, 이번 범위 밖)이 생길 때까지 자리만 둔다.

### 3.3 "판정 · 품번은 OPMS 값만 쓴다" 원칙 확인

**유지된다.** 작업 모드가 읽는 확정본에 들어 있는 품번은 OPMS `:Part.part_no` 조회값이고, 판정은 OPMS가 준 결과(verdict · 이유 · 근거 규칙 · `ontology_version`)를 **그대로** 담는다. 작업자 화면은 이것을 보여 주기만 한다(PDM이 점수 · 판정을 다시 계산하지 않는다). 단독 시연 모드(`standalone`)에서는 번호와 판정이 데모용임을 화면에 표시한다.

## 4. 사용자가 정해야 하는 것 (먼저 정할 것부터)

| 순서 | 질문 | 왜 중요한가 | 제안 |
|---|---|---|---|
| 1 | **작업자 화면은 Onto PDM 안의 화면인가, 현장의 MES 단말에 들어가는 화면인가?** 작업 실행 · 실적 기록은 누가 하나(PDM인가 MES인가)? | 범위가 크게 달라진다. 이것에 따라 6~7번(기록 · 로그인)이 정해진다 | 일단 PDM 안의 "작업 모드"로 시작하고 MES와의 경계는 나중에 |
| 2 | **판정이 "실패"(멈춤)일 때 현장 규칙은?** 진행을 완전히 막나, 경고만 하나, 누가 해제하나, 담당자 호출은 어떻게 하나? "알 수 없음"은 막나? | 안전 · 품질 정책이라 시스템이 임의로 정하면 안 된다 | 가장 안전한 쪽: 실패는 막고 담당자만 해제, 알 수 없음은 담당자 확인 |
| 3 | **작업자가 보는 데이터는 "확정 · 발행된 작업표준"만으로 할까?** 판정은 발행 때 고정할까, 실시간으로 받을까? | 3.2의 (가)/(나). 구조가 달라진다 | 확정본 + 판정 스냅샷 (가) |

| 5 | **오프라인(네트워크 없이)이 필요한가?** | 필요하면 확정본을 단말에 미리 내려받아 둬야 하고(3.2 (가) 필요), 규칙이 바뀔 때의 갱신 절차가 필요 | 필요 여부부터 확인. 필요하면 (가) 필수 |
| 6 | **"확인했다" 표시 · 단계 완료 기록 · 담당자 호출을 남길까?** (조회 전용의 예외) | 현장 기록이 없으면 사고 때 추적이 안 되고, 있으면 MES 실적과 겹친다 | 남기되 설정은 바꾸지 못하게. MES 실적(F-MES-5)과 이어 붙일지는 질문 1 |

## 5. 이 제안이 영향을 주지 않는 것

- OPMS와의 역할 분담(판정 · 품번 = OPMS, 절차 · 토크 · 공구 · 주의 = PDM)은 그대로다.
- 규칙 8개(조립 안내 값)는 그대로 쓴다. 규칙이 많아지면 확정본 만드는 쪽의 일이 늘 뿐이다.
- 실제 CAD 파일(STEP)이 아직 없다(PRD 12장 3번). 작업 모드의 시연은 지금처럼 가상 제품(제어 박스 · 시계)으로 가능하지만, **현장 확인은 실제 파일이 필요하다**.
