# Onto PDM 웹 (프론트엔드)

React 18 + TypeScript + Vite 8 + Tailwind CSS 3 (Node 20.19 이상 또는 22.12 이상). **가짜(목) 데이터는 없다.** 보유 품번은 OPMS(백엔드가 Neo4j 를 읽기만 한다)에서, **조립 규칙 · 작업표준은 PDM 규칙집(저장소 `rules/`)에서 백엔드가 읽어 준다.** 제품 · BOM 은 OPMS 에 아직 없어 비어 있고, 읽어 올 곳이 없는 화면은 "연결되면 표시돼요"라고 말한다. CAD에서 계산하는 것(제조 순서 · 속성 후보 · 형상으로 본 볼트 종류)은 연결과 상관없이 동작한다.
화면이 쓰는 API 형태(`src/api/types.ts`의 `PdmApi`)는 [docs/pdm-design.md](../docs/pdm-design.md) 9장의 REST API와 같다.

## Quick Start

패키지는 **pnpm**으로 관리한다. 버전은 `package.json`의 `packageManager`(`pnpm@12.11.2`)에 고정돼 있다.

```bash
npm install -g pnpm@12.11.2   # pnpm이 없을 때 한 번
cd web
pnpm install
pnpm dev                      # http://localhost:5173
```

**전체 실행(OPMS 연동): OPMS 를 먼저 켜고, 그 다음 PDM 을 켠다.** 저장소 루트에서 `node tools/dev-pdm.mjs` 를 실행하면 OPMS 의 Neo4j 가 응답하는지 먼저 확인하고(안 켜져 있으면 안내 후 종료), 파일 서버(8788) · PDM 백엔드(8100) · 웹 개발 서버를 한 번에 띄운다. Ctrl+C 로 셋 다 종료된다. Neo4j 접속 정보는 환경 변수 `PDM_NEO4J_*` 또는 OPMS 저장소의 `.env`(`NEO4J_*`)를 읽기만 해서 쓰고 화면·파일에 남기지 않는다. 백엔드 설치는 [backend/README.md](../backend/README.md).

| 명령 | 하는 일 |
|---|---|
| `pnpm dev` | 개발 서버만 (코드를 고치면 바로 반영). 백엔드가 꺼져 있어도 화면은 열리고 "연결 안 됨" 이유를 보여 준다 |
| `pnpm test` | 화면 · 추출 · 분류기 테스트 (Vitest, jsdom). 데이터가 필요한 화면은 시험 안에서만 만든 작은 데이터(`testApi.ts` · `testProduct.ts` 등)를 API 로 주입해 본다 |
| `pnpm e2e` | 실제 브라우저 테스트 (Playwright). Windows는 설치된 Edge, 그 밖의 OS는 `pnpm exec playwright install chromium` 한 번. 서버 DB(`/api/cads`)와 보관소(`/api/files`)는 시험이 가짜 서버(`e2e/fake-server.ts`)로 자동으로 가로채 이 컴퓨터의 실제 DB 에 쌓이지 않고, 10분 캐시는 가짜 시계(`context.clock`)로 확인한다 |
| `pnpm typecheck` | 타입 검사만 |
| `pnpm build` | 타입 검사 + 프로덕션 빌드 (`dist/`) |
| `pnpm preview` | 빌드 결과 확인 http://localhost:4173 |
| `pnpm add <패키지>` · `pnpm add -D <패키지>` | 의존성 추가 (`pnpm-lock.yaml`이 함께 바뀐다) |
| `pnpm install --frozen-lockfile` | CI처럼 lock 파일 그대로 설치 |

- `npm install` · `npm run`은 `devEngines` 설정으로 막혀 있다. 실수로 `package-lock.json`이 다시 생기는 것을 막기 위해서다.
- VS Code의 npm 스크립트 탐색기를 쓰면 설정에서 `"npm.packageManager": "pnpm"`으로 바꾼다.

## 화면

| 경로 | 화면 |
|---|---|
| `/` (등록한 CAD) | 올린 CAD 의 **파일 자체는 서버 DB(`/api/cads`)가 정본**이고(서버가 파일 보관소에도 복사), 이 브라우저(IndexedDB)는 **10분 캐시**다. 연 CAD 는 마지막으로 쓴 때(열림 · 열려 있는 동안 15초 하트비트 · 창 닫힘)부터 10분 동안 캐시에 남아, 창을 닫았다 열어도 서버를 부르지 않고 바로 열린다. 10분이 지나면 파일 내용만 비우고 목록 정보는 남겨(`서버에서 불러와요`) 열 때 서버 DB 에서 받아 다시 캐시에 올린다. 서버에 못 보낸 CAD(서버가 꺼진 동안 올린 것)는 `이 브라우저에만`으로 표시되고 캐시에서 비우지 않으며, 서버가 돌아오면 자동으로 올린다. 마지막에 작업하던 CAD 와 고른 부품 · 단계(`onto-pdm.cad.session`)는 10분 안에 다시 열면 복원된다. 목록에서 제거하면 서버 DB 의 사본도 목록에서 빠진다(내용은 DB 에 남아 같은 파일을 다시 올리면 되살아난다). CAD 마다 확정한 속성 결정 · 볼트 종류도 기억된다. "보관소에서 가져오기"로 파일 보관소에만 있는 CAD 를 목록에 가져온다 |
| `/` | **CAD 스튜디오(메인)**: 홀로그램 3D 분해도 + 제조 순서 + 온톨로지. CAD를 올리면 구조에서 제조(조립) 순서를 나눈다. **보유 품번 매칭 · 온톨로지 그래프는 OPMS 에, 조립 안내(HUD) 카드는 PDM 규칙집에 연결돼야 나온다**(연결 전에는 "연결되면 표시돼요" 안내). 연결되면 단계마다 쓰이는 부품을 보유 품번과 매칭하고(확정 · 후보 · 미보유), 부품을 고르면 분류 사슬 · 재료 · 속성 · 별칭 · 사용처를 그래프로 본다. 머리에는 **CAD 올리기만** 있다(사양서 올리기 · BOM 올리기는 삭제됨, 사용자 지시, 2026-11-11) |
| `/` (속성 탭: 형상으로 본 볼트 종류) | 부품을 고르면 뷰어에서 **부품 메시를 읽어**(`getPartGeometry`) 볼트 형상을 분류한다. 속성 패널 위쪽의 **"형상으로 본 볼트 종류"** 블록에 후보(육각구멍붙이 · 육각 · 육각플랜지 · 버튼헤드 · 접시머리)가 점수 · 근거와 함께 나오고, OPMS 에 아직 없는 분류(버튼헤드 · 접시머리)는 **"제안(미등록)"** 으로만 표시한다. 점수가 가깝거나 구동부 구멍이 안 보이면 "후보가 여러 개예요"라고 알리고 하나로 정하지 않는다. 사람이 **이 종류로 확정**하면(CAD 마다 기억) ① (OPMS 에 연결되면) 확정한 나사 규격 · 길이 · 머리 모양이 보유 품번 매칭 조건과 조립 규칙 선택의 입력으로 흐르고(코드는 데이터가 비어 있어도 동작하며, 후보 없음 · 규칙 없음으로 보인다), ② 미등록 분류는 OPMS 분류 등록 요청 **초안**(클래스 · 정의 · 근거)이 붙어 복사해 전달할 수 있다. 작은 부품은 한가한 때 하나씩 미리 분석하고, 큰 부품은 고를 때만 분석한다. **실제 STEP 4종(HCR 로봇)으로 검증했다**: 소켓 헤드 볼트 119개 부품을 모두 읽고(호칭 · 육각구멍 크기 119/119) 큰 비볼트 141개에서 오탐 0, 한 부품에 합쳐진 볼트 · 머리만 모델링된 볼트 · 골지름으로 그린 몸통도 읽는다(정답 일부는 이름 · ISO 치수 기준이고, 소켓 외 머리의 실제 STEP 은 확인하지 못했다). 분류기와 검증: [docs/fastener-classification.md](../docs/fastener-classification.md) |
| `/` (속성 탭: OPMS 필수 속성) | 볼트로 분류된 부품에는 형상 블록 아래에 **"OPMS 필수 속성 · 확인 K/N"** 체크리스트가 나온다. OPMS 분류가 요구하는 필수 속성(예: 육각구멍붙이볼트 8개)을 **확정 · 추정(CAD 추정 · 이름에서 추정) · OPMS가 채워요(나사 방향 → 오른나사, 피치 → 보통 나사 값; 비어 있다고 세지 않음) · 미확인** 순으로 보이고, 재질 · 표면처리 · 강도 등급은 "CAD로 알 수 없어요 — 사양서·BOM에서 와요. 지금은 등록 요청 때 OPMS 검토 화면에서 채워요"라고 말한다. 값이 OPMS 범위(길이 ≥3 mm · 육각구멍 ≥1.5 mm)에 걸리면 호박색 확인 칩이고(빨강 없음), OPMS 에 없는 분류(버튼헤드 · 접시머리)는 상위 분류(볼트) 기준이라고 밝힌다. 분류별 규칙은 백엔드 `/opms/classes/{code}` 를 한 번만 읽고(`PdmApi.opms.getClassSpec`), OPMS 에 연결되지 않으면 "OPMS에 연결되면 필수 속성을 확인해요"이다. 요청 초안에는 미확인 필수 속성이 실린다 |
| `/` (조립 안내 HUD: 규칙집) | 부품을 고르면 3D 위 카드와 아래 자막에 **규칙집(`rules/`)이 고른 조립 규칙**이 뜬다(백엔드 `POST /rulebook/select`). 사람이 확정한 볼트 종류 · 확정한 나사 규격 · 길이만 보내면 **"확정 기준"**, 확정 전에는 형상이 추정한 종류 · 규격을 **"CAD 추정 기준"**(호박색)으로 보내고 규칙 적용을 단정하지 않는다("적용될 것으로 보는 규칙"). 카드는 ① **적용되는 규칙**(값 · 사용설명서 경고 문구 + 쪽 번호 · 공구 이름, 값이 비어 있는 곳은 "작성 필요 G-0xx", 확정값이 아닌 값은 점선), ② **확정하면 적용되는 규칙**("알아야 확정돼요: 이 볼트의 역할 · 나사 규격 · 로봇 모델")을 구분하고, 모든 규칙에 "초안 · 검토 전"을 붙인다. **역할**(베이스 고정 볼트 · 툴 고정 볼트 …)은 CAD 로 알 수 없어 카드에서 사람이 고른다(고르면 그 역할의 규칙이 정해지고, 다시 누르면 해제). **로봇 모델**(HCR-3A · 5A · 12A)은 파일 · 부품 이름에서 하나로 읽을 때만 보낸다(`ruleModel.ts`, 모호하면 "모델 미확인"). 같은 요청은 한 번만 보내고, 분류를 모르는 부품(판 등)은 "종류를 알 수 없어 규칙을 고를 수 없어요"라고 말하며 묻지 않는다. 규칙집을 못 읽으면(백엔드 꺼짐 · `rules/` 오류) 이유를 말한다(빨강 아님) |
| `/products/:code` | **제품 연결 그래프**: 제품 → 조립품 → 부품이 BOM 관계로 이어진 3D 그래프(회전 · 확대, 목록 보기 전환 가능). 노드를 고르면 문서와 적용되는 조립 규칙이 묶여 나온다. **데이터를 읽어 올 곳(OPMS)이 없으면 안내만 보인다** |
| `/rules`, `/rules/:id` | **조립 규칙**(PDM 규칙집, 백엔드 `/rulebook/*`): 상태줄("규칙집 적재됨 · 규칙 23 · 작업표준 10 · 공백 19 · 모두 초안(검토 전)" · 값 출처별 수), 규칙 목록(공정 칩 · 분류 · 역할 · 출처 · 모델 필터 · 검색, 값 출처 칩 · 미확정 값 수 · 제안(미등록) 분류), 상세(적용 대상 · 값 표 · 모델별 조건표 · 주의사항(경고 · 주의 · 안내 + 쪽 번호) · 공구 이름 · 이 규칙을 쓰는 작업표준 · 작성이 필요한 곳), 온톨로지 3D 보기. **값마다 출처 배지**: 사용설명서(쪽 번호, 초록) · CAD 추정(호박색) · 표준 참고(승인 전) · 근거 없음 · 작성 필요 G-0xx(회색 점선). 확정값이 아닌 값(CAD · 근거 없음 · 추정)은 확정값처럼 보이지 않게 점선으로 구분한다. 모두 초안(검토 전). 백엔드가 꺼져 있거나 `rules/` 에 오류가 있으면 이유를 말하고(오류 목록 펼침, 빨강 아님) 다시 시도할 수 있다 |
| ~~`/items`~~ | 품목 목록. 삭제됨(사용자 지시, 2026-11-11) |
| ~~`/items/:품번`~~ | 품목 상세(개요 · BOM 정전개 · 사용처 · 문서 · 3D · 이력). 삭제됨(사용자 지시, 2026-11-11) |
| `/products` | 제품과 최상위 조립품 (연결 전에는 안내만 보인다) |
| ~~`/requests*`, `/admin/*`, `/bom-import`~~ | 내 등록 요청 · 관리자 화면(등록 요청 · 분류 제안 · 그래프 발행 상태) · BOM 가져오기. 삭제됨(사용자 지시, 2026-11-11). 스튜디오의 사양서 올리기 · BOM 올리기도 삭제됨 |
| `/mes` | **작업 표준**: 규칙집의 **작업표준서**(목록 + 상세: 목적 · 표준 시간(근거가 없어 "표준 시간 없음 — 근거 없음") · 공구 · **작업 순서**(조건 · 대상 · 규칙 링크 · 출처 배지) · **주의사항**(사용설명서 경고 문구 + 쪽 번호) · 품질 확인(판정 기준) · **점검 항목 표**(주기) · CAD 구조에서 센 체결 부품(CAD 추정) · 관련 규칙 · 작성이 필요한 곳)와 "작성 필요 목록"(G-0xx: 필요한 것 · 이유 · 채울 곳), 인쇄 버튼(메뉴 · 목록은 감추고 상세만 흰 종이에). 제품 · BOM 이 있으면(OPMS 연동 뒤) 제조 BOM + 작업 단계 묶음 미리보기도 함께 나온다. 발행 · 내려받기 · 이력은 삭제됨(사용자 지시, 2026-11-11) |

## 데이터와 연결 (가짜 데이터 없음)

- 앱에는 목(mock) 데이터가 없다(삭제됨, 사용자 지시, 2026-11-11). 기본 API([src/api/emptyApi.ts](src/api/emptyApi.ts))는 비어 있는 구현이라 보유 품번 · 규칙 · 제품 · 문서를 모두 "없음"으로 돌려주고, `connected: false` 로 연결되지 않았음을 알린다.
- 화면은 `connected` 를 보고, 없다고 말하는 대신 **"OPMS에 연결되면 표시돼요"** 안내([`NotConnected`](src/components/ui.tsx))를 보인다. 오류가 아니라 상태라서 빨강을 쓰지 않는다. 연결 전에도 CAD에서 계산하는 것(제조 순서 · 크기에서 계산한 속성 후보 · 형상으로 본 볼트 종류 · 등록 요청 초안)은 그대로 보인다.
- 사용자 프로필(사진 · 이름 · 역할) · 사용자 전환 · 관리자 모드 · 데모 초기화는 없다(삭제됨).
- API 계약([src/api/types.ts](src/api/types.ts)의 `PdmApi`)은 남아 있다. **OPMS 읽기**(분류 · 부품 · 매칭)와 **규칙집 읽기**(조립 규칙 · 작업표준서 · 공백 · 규칙 고르기)는 HTTP 구현([src/api/httpApi.ts](src/api/httpApi.ts))으로 연결했다(아래 "백엔드로 바꾸기"). 제품 · BOM · MES 는 OPMS 에 없는 데이터라 http 모드에서도 비어 있다.
- 시험은 데이터가 필요한 화면마다 작은 데이터를 시험 안에서만 만들어 API 로 주입한다(앱에는 들어가지 않는다): [studio/testApi.ts](src/pages/studio/testApi.ts), [graph/testProduct.ts](src/pages/graph/testProduct.ts), 규칙 · 작업 표준 시험 안.
- 사양서 · BOM 본문에서 값을 뽑는 순수 함수(`src/extract/spec.ts` · `extractSpecAttributes`)는 남겨 두었지만 지금은 화면에서 쓰지 않는다(나중에 다시 붙일 수 있게).

## 디자인

디자인은 **OPMS(`ernest_hemingway_OPMS/web`)를 따른다.** 둘이 충돌하면 OPMS가 기준이다.

| 무엇 | 어디 | OPMS와의 관계 |
|---|---|---|
| 색 · 글꼴 · 간격 · 모서리 토큰 | [tailwind.config.ts](tailwind.config.ts) | OPMS `web/tailwind.config.ts`와 같은 값. 바뀌면 그대로 다시 복사한다 |
| 앱 셸(글래스 사이드바 · 머리 · 접기 · 드로어) | [src/styles.css](src/styles.css) 위쪽, [AppShell.tsx](src/components/AppShell.tsx) | OPMS `index.css` · `Layout.tsx`와 같은 구조. 메뉴만 PDM 것 |
| 페이지 부품(`.card` `.btn` `.table` `.badge` `.tabs` …) | [src/styles.css](src/styles.css) 아래쪽 | PDM 화면이 쓰는 클래스를 OPMS 토큰 위에서 정의 (화면 코드는 그대로) |
| 글꼴 · 아이콘 | [index.html](index.html) | Inter · JetBrains Mono · Material Symbols (Google Fonts) |

- 디자인 원칙 문서는 OPMS의 `web/docs/DESIGN.md`다. 여기에 복사하지 않는다.
- 다크 모드는 없다 (OPMS가 없다).
- `tone-${tone}`처럼 클래스 이름을 이어 붙여 쓰는 규칙은 Tailwind가 미사용으로 지우므로 `styles.css`의 레이어 밖에 둔다.
- 사이드바 접기는 `Ctrl/⌘+B`, 상태는 `localStorage`의 `onto-pdm.sidebar`.

## 백엔드로 바꾸기

`VITE_API_MODE` 로 API 구현을 고른다 ([src/api/client.ts](src/api/client.ts)):

| 값 | 구현 | 기본으로 쓰이는 곳 |
|---|---|---|
| `http` | [httpApi.ts](src/api/httpApi.ts): PDM 백엔드(`/api/v1/pdm`)를 거쳐 **OPMS(Neo4j)를 읽기만** 한다 — 분류 · 부품 · 확정한 규격으로 보유 품번 후보 찾기 · 연결 상태 — 그리고 **규칙집(`rules/`)을 읽기만** 한다(`PdmApi.rulebook`: 규칙 · 작업표준서 · 공구 · 공백 · `selectRules`) | `pnpm dev` (개발 서버) |
| `empty` | [emptyApi.ts](src/api/emptyApi.ts): 읽어 올 곳 없음(가짜 데이터 없음) | 빌드 · 시험 · E2E 기본 서버 |

- 개발 서버는 `/api/v1/pdm` 을 백엔드(`PDM_API_PORT`, 기본 8100)로 넘긴다(vite.config.ts). 백엔드는 `backend/README.md` 의 "OPMS 읽기"대로 켠다(`PDM_NEO4J_*`). 백엔드가 꺼져 있어도 화면은 열리고, **스튜디오 오른쪽 위의 연결 상태 줄**이 이유를 말한다: OPMS 연결됨(온톨로지 버전 · 부품 수) / PDM 백엔드가 꺼져 있어요 / OPMS에 연결하지 못했어요 / 읽기 설정이 없어요 / 계정을 받아주지 않았어요 / 온톨로지가 아직 없어요 + "다시 시도"(연결이 돌아오면 매칭을 다시 한다). 빨강을 쓰지 않는다.
- `PdmApi.connected` 는 제품 · MES 데이터가 있는가(http 모드에서도 false), `PdmApi.opms` 는 OPMS 분류 · 부품을 읽는 길, `PdmApi.rulebook` 은 조립 규칙 · 작업표준서를 읽는 길이다(둘 다 http 모드에만 있다).
- **규칙집**: 규칙 · 작업표준은 OPMS 에 없는 PDM 소유 지식이라 저장소 `rules/` YAML 을 백엔드가 읽어 준다([backend/README.md](../backend/README.md) · [docs/work-standards.md](../docs/work-standards.md)). 웹은 응답(snake_case)을 camelCase 로 바꿔 읽고(값 자리의 `null` 은 "근거가 없어 비어 있다"는 뜻이라 남긴다), 값 · 출처 · 근거 문구를 **웹 코드에 박지 않는다**(기계 키의 한글 이름만 `pages/rules/rulebookUi.tsx` 에 있다). 상태(`rulebook.status()`)는 적재됨 · `rules/` 검증 오류 · 파일 없음 · 백엔드 꺼짐을 구분한다. 규칙 고르기(`selectRules`)는 같은 (분류 · 상위 분류 · 속성 · 역할 · 모델) 요청을 한 번만 보낸다. HUD 가 보내는 것: 확정 기준이면 확정한 값만, 추정 기준이면 형상이 추정한 값 — 추정 결과는 "적용될 것으로 보는 규칙"으로만 보인다.
- **보유 품번은 이름이 아니라 규격으로 찾는다**(OPMS 부품에는 이름이 없다): 속성 탭에서 확정한 나사 규격 · 길이(· 머리 모양 · 볼트 종류)가 먼저이고, **확정 전에도 CAD 형상 분석이 충분히 확실하게 추정한 규격**(1위 점수 ≥ 0.6, 구멍까지 읽어 종류를 단정할 수 있는 볼트)으로 찾아 **"후보 N개 · 추정"** / **"미보유 · 추정 규격"** 으로 보인다. 자동 확정은 없다: 품번 확정은 늘 사람이고, 사람이 규격을 확정하면 "추정"이 사라진다. 추정하지 못한 부품(볼트가 아님 · 단순화 모델)은 "규격 확정 필요", OPMS 를 못 읽으면 "연결 안 됨"이다(둘 다 "미보유"가 아니다). 같은 규격은 OPMS 에 한 번만 묻고(요청 중복 제거) 동시에 4개까지, 고른 부품이 먼저다. 후보가 여럿이면 온톨로지 탭에서 일치 근거를 보고 하나를 고른다. 후보의 일치는 퍼센트가 아니라 "확인한 K개 속성이 모두 일치 · 미확인 M개(길이, 재질 …)"로 보인다(미확인이 있으면 '100% 일치'라고 말하지 않는다). 자세히는 [docs/fastener-classification.md](../docs/fastener-classification.md) 12장.
- 시험: [src/api/testBackend.ts](src/api/testBackend.ts) 가 백엔드 응답을 흉내 내는 가짜 fetch(시험 전용)이다. E2E 는 개발 서버를 둘 띄운다(`E2E_PORT` = empty, `E2E_PORT + 1` = http; `e2e/opms-connection.spec.ts` · `e2e/rulebook.spec.ts` 는 백엔드 호출을 `page.route` 로 가로채 실제 백엔드 · OPMS 에 의존하지 않는다). 가짜 규칙집은 실제 `rules/` 에서 대표 규칙 5 · 작업표준서 3 · 공백 4 를 옮긴 것이다(시험 안에서만).
