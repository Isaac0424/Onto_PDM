# 조립 규칙 사양 (가상 회사 "온토전자")

CAD 위에 뜨는 조립 안내(카드 · 자막)가 읽는 **사내 규칙**을 어떻게 정의하는지 설계한 문서다.
실제 회사의 규칙이 아니라 **가상 회사의 목업**이고, 숫자는 화면 시연용이다. 용접 조건 같은 값을 실제 작업에 쓰지 않는다.
코드: [web/src/api/mock/assemblyRules.ts](../web/src/api/mock/assemblyRules.ts) · 화면: [web/src/pages/studio/AssemblyHud.tsx](../web/src/pages/studio/AssemblyHud.tsx)

## 1. 한눈에: 규칙이 화면에 뜨기까지

```
사내 규칙 문서(작업표준서 · 조건표)          ← 사람이 쓴다 (여기서는 목업)
   ↓ 구조화 (온톨로지: 공정 · 규칙 · 조건 · 주의사항)
Neo4j (OPMS 방식: YAML → 컴파일 → 그래프)
   ↓ 부품의 분류 · 치수 · 속성으로 적용할 규칙을 고른다
CAD 위 안내: 오른쪽 카드(값 · 주의사항 · 공구) + 아래 자막(지금 할 일)
```

규칙은 **부품 이름이 아니라 부품의 분류와 속성**에 붙는 것이 원칙이다. 목업도 이 방식을 따른다([5.2](#52-규칙은-분류와-속성에-건다)): 분류와 속성이 들어온 부품은 분류로 규칙을 고르고, 이름만 가진 CAD 부품은 이름 패턴으로 찾는다. 두께 같은 값은 `thickness` 속성이 있으면 그것을, 없으면 CAD 크기에서 계산한다.

## 2. WPS 말고 필요한 문서

| 문서 | 무엇이 들어 있나 | 규칙에서 쓰는 곳 | 목업 |
|---|---|---|---|
| **작업표준서** (SOP / 작업지도서) | 공정별 작업 순서, 방법, 주의사항 | 카드의 주의사항 · 자막 | SP-* 전체 |
| **체결 토크 기준표** | 나사 규격 · 재질별 조이는 힘, 순서 | 볼트 체결 | SP-FAS-01 |
| **용접절차서 (WPS)** | 모재 두께별 개선 형상 · 용접봉 지름 · 조건 | 용접 | SP-WLD-01 (가상 표) |
| **끼워맞춤 · 압입 기준** | 구멍과 축의 공차, 압입력 상한 | 압입 | SP-PRS-01 |
| **정전기(ESD) · 안전 지침** | 전자부품 취급, 보호구, 위험 작업 | 전자부품 장착, 용접 | SP-ELC-01 |
| **공정 흐름도 (Routing)** | 단계 순서, 어느 설비에서 하는지 | 제조 순서 | CAD 구조에서 자동 |
| **검사 기준서** | 무엇을 · 어떻게 · 합격 기준 | (다음 단계) 단계 끝의 확인 항목 | 없음 |
| **공구 · 지그 목록** | 단계별 필요한 도구, 교정 기한 | 카드의 공구 | 규칙에 포함 |
| **불량 유형과 조치** | 흔한 불량과 대응 | 주의사항의 근거 | 주의사항에 포함 |
| **재료 성적서 · 인증서** | 재료의 실제 성분 · 시험 결과 | 품목 문서 연결 | 문서 관리 |

실제 도입할 때 가장 먼저 구해야 할 것은 **작업표준서 · 토크표 · 용접절차서** 세 가지다. 나머지는 이후에 붙여도 된다.

## 3. 공정 종류 (용어)

| 공정 | 쉽게 말하면 | 이번 규칙 |
|---|---|---|
| 체결 | 나사 · 볼트로 조인다 | SP-FAS-01, SP-CVR-01 |
| 용접 | 열로 금속 두 개를 녹여 붙인다 | SP-WLD-01 |
| **압입 (press fit)** | 구멍보다 **아주 조금 큰** 축이나 부품을 **프레스로 눌러 끼운다**. 나사도 용접도 없이 꽉 끼워서 고정된다. 베어링, 핀, 시계 유리가 대표적 | SP-PRS-01 |
| 장착 | 부품을 정해진 자리에 올린다 (기판, 스페이서) | SP-ELC-01, SP-SPC-01 |
| 삽입 | 구멍이나 틈에 끼운다 (배터리, 버튼) | SP-BAT-01, SP-SW-01 |
| 커버 조립 | 외장을 닫는다 | SP-CVR-01 |

접착, 도장, 납땜 같은 공정은 같은 구조로 나중에 추가한다.

## 4. 온톨로지 구조 (OPMS 방식)

OPMS는 규칙을 `rules.yaml` · `constraints.yaml`에 쓰고 Neo4j로 컴파일한다. 조립 규칙도 같은 방식으로 얹는다.

| 개념 | 라벨 | 설명 |
|---|---|---|
| 공정 | `Operation` | 체결 · 용접 · 압입 … 분류 트리 (`Joining` → `Fastening` / `Welding` / `PressFit`) |
| 규칙 | `AssemblyRule` | `id`, 이름, 출처 문서 |
| 조건 | `Condition` | 규칙이 적용될 때: 분류, 속성 범위 (`thickness`) |
| 값 | `Parameter` | 규칙이 내놓는 값: 토크, 용접봉 지름 |
| 주의사항 | `Caution` | 규칙이나 공정이나 분류에 붙는 경고 |
| 공구 | `Tool` | 필요한 도구 |

```
(:AssemblyRule {id:'SP-FAS-01'})-[:FOR]->(:Operation {code:'Fastening'})
(:AssemblyRule)-[:APPLIES_TO]->(:Class {code:'HexBolt'})        ← OPMS의 분류 노드를 그대로 가리킨다
(:AssemblyRule)-[:REQUIRES]->(:Tool)
(:AssemblyRule)-[:WARNS]->(:Caution)
(:AssemblyStep)-[:FOLLOWS]->(:AssemblyRule)                       ← CAD 단계가 어느 규칙을 따르는지
(:AssemblyStep)-[:USES]->(:PdmItem)                               ← 그 단계에 쓰는 보유 품번
```

규칙 정의 예 (YAML, 값은 가상):

```yaml
assembly_rules:
  SP-FAS-01:
    name: 소형 나사(M3) 체결
    operation: Fastening
    applies_to: {class: Bolt, where: {threadSize: M3}}
    parameters:
      torque: {value: 0.6, unit: N·m, tolerance: 10%}
      sequence: 대각선, 2회 (50% → 100%)
    cautions: [나사산이 상하면 폐기, 같은 나사 3회 초과 재사용 금지]
    tools: [토크 드라이버 0.2~1.0 N·m]

  SP-WLD-01:
    name: 박판 용접 (가상 조건표)
    operation: Welding
    applies_to: {class: WeldedJoint}
    lookup:                       # 얇은 쪽 모재 두께 → 값 (OPMS의 lookup 표와 같은 방식)
      key: thickness
      table:
        "<1.5": {groove: I형, filler: Φ1.0, gap: 0 mm}
        "<3":   {groove: I형, filler: Φ1.6, gap: 0~0.5 mm}
        "<6":   {groove: V형 60°, filler: Φ2.4, gap: 1~2 mm}
        ">=6":  {groove: V형 60° 다층, filler: Φ3.2, gap: 2~3 mm}
```

입력 · 출력 **포트 방향**은 규칙이 아니라 부품의 **속성**(`inputPortSide: left`, `outputPortSide: right`)으로 두고, 제품군 제약(`constraints`)으로 검사한다. 조립 단계에서 어긋나면 경고한다.

"이 규칙이 적용되는 품목" 목록(`usedBy`)은 목 API가 아직 **품목 이름**으로 찾는다. 조립 안내(`getAssemblyGuides`)는 분류와 속성으로 규칙을 고른다 (PRD F-RUL-4, 아래 5.2).

### 5.2 규칙은 분류와 속성에 건다

규칙 정의(`RuleDef`)는 두 가지 조건을 가진다.

| 조건 | 뜻 | 예 (SP-FAS-01) |
|---|---|---|
| `classes` | 규칙이 걸리는 **분류 이름**. 부품의 분류(`className`)가 같거나, `체결류 › 볼트` 같은 분류 사슬에 들어 있으면 걸린다 | `['볼트']` |
| `when` | 분류가 맞은 부품에 더하는 **속성 조건** | 나사 규격(`threadSize`)이 `M3` |
| `match` | 분류를 모르는 부품(이름만 있는 CAD 부품)에 쓰는 **이름 패턴**. 하위 호환 | `/(나사\|볼트).*M3\|M3.*(나사\|볼트)/` |

`getAssemblyGuides`가 부품 하나(`이름 · 크기 · 분류 · 속성`)에 규칙을 고르는 순서:

1. **분류가 있고 규칙에도 분류가 있으면 분류로만 판단한다.** 분류가 다르면 이름이 비슷해도 걸리지 않는다. 속성 조건(`when`)이 있으면 함께 본다.
2. 분류를 모르거나 규칙에 분류가 없으면(기판 · 스페이서 · 용접 · 압입) **이름 패턴**으로 찾는다.
3. 걸리는 규칙이 둘 이상이면 **정의 순서가 앞선 규칙**이 쓰인다. 겹치는 규칙은 아래 검증이 경고한다.

```text
{ name: '기판 고정 나사', className: '볼트', attributes: { threadSize: 'M3' } }  → SP-FAS-01   (이름에 규격이 없어도 걸린다)
{ name: '볼트 M4x10',    className: '볼트', attributes: { threadSize: 'M4' } }  → (없음)       (속성 조건이 안 맞는다)
{ name: '볼트 M3x8',     className: '커버' }                                    → SP-CVR-01   (분류가 우선이다)
{ name: '기판 나사 M3' }                                                       → SP-FAS-01   (이름만: 이름 패턴)
```

**값 계산**: 두께는 확정된 `thickness` 속성이 있으면 그 값을 쓰고, 없으면 CAD 크기의 가장 얇은 치수를 쓴다. 커버의 필요 나사 길이는 `두께 + 1.5 × 나사 지름(4.5 mm)`이다 (두께 8 mm → ≥ 12.5 mm, 사용 나사 M3×12는 부족으로 표시).

규칙에 쓰는 분류 이름은 시드 분류(볼트 · 하우징 · 커버 · 감속기 · 서보 모터 · 배터리 · 스위치 · 버튼)와 맞춘다. 분류가 아직 없는 부품 종류(기판 · 스페이서 · 접합 부품 · 유리 · 크리스털)의 규칙은 이름으로 찾고, 상세의 "적용 조건"에 그 사실을 적어 둔다. 이 부품들에 분류가 생기면 `classes`를 채운다.

### 5.3 규칙 검증 (PRD F-RUL-6)

규칙 화면 위쪽의 **규칙 검증** 영역이 정의를 점검한 결과를 보인다 ("오류 N · 경고 M", 문제 목록, 규칙 번호 링크, "다시 검증", 접기). 문제가 있는 규칙은 목록에 작은 표식이 붙고, 상세 "정보" 탭에 그 규칙의 결과가 따로 나온다. 코드: `validateRuleDefs(defs)` / `validateRules()` ([assemblyRules.ts](../web/src/api/mock/assemblyRules.ts)), API: `validateAssemblyRules()`.

| 코드 | 심각도 | 걸리는 경우 |
|---|---|---|
| `no_scope` | **오류** | 적용 대상(분류 · 부품 종류)이 비어 있다 |
| `missing_value` | **오류** | 적용 조건이 없다 · 값이 하나도 없다 · 값 이름이나 내용이 비었다 · 조건표에 빈 칸이 있다 |
| `no_source` | **오류** | 출처 문서가 비었다. **경고**: 검토 전(draft) 규칙 — 가상 값이라 승인된 출처가 없다 |
| `empty_table` | **오류** | 조건표에 행이 없거나 행의 열 수가 머리와 맞지 않는다 |
| `no_caution` | 경고 | 주의사항이 없다 |
| `overlap` | 경고 | 한 규칙의 대표 부품에 다른 규칙도 걸린다 (순서가 앞선 규칙이 쓰인다) |
| `unused` | 경고 | 규칙이 자기 대표 부품에도 걸리지 않는다 (조건이 잘못됐다) |

- **오류**는 쓸 수 없는 규칙, **경고**는 쓸 수는 있지만 확인할 것이다. 화면에서는 둘 다 주황 · 호박색으로 구분한다(오류 = 진한 주황 + 왼쪽 굵은 선, 경고 = 옅은 호박색). 의도치 않은 빨강을 쓰지 않는다.
- 지금 규칙 11개의 결과: **오류 0, 경고 2** (검토 전 규칙 SP-WLD-01 · SP-PRS-01). 승인 규칙은 모두 깨끗하다.
- `RuleIssue.code`에는 "검토 전"에 맞는 전용 코드가 없어 가장 가까운 `no_source`를 쓰고 메시지에 "검토 전 규칙(가상 값)"이라고 밝힌다.
- 시험은 문제 없는 규칙과 일부러 깨뜨린 정의(`validateRuleDefs`에 직접 넣는다)로 각 코드를 확인한다.

## 6. PDM과 MES의 역할

**MES**(제조실행시스템)는 공장 현장에서 "지금 무엇을 어떻게 만들고 있나"를 실행 · 기록하는 시스템이다.

| MES가 하는 일 | 설명 |
|---|---|
| 작업지시 | "오늘 이 제품을 몇 개, 이 순서로 만들라"는 지시를 받아 작업자에게 보여 준다 |
| **작업 안내 화면** | 작업자가 단말에서 단계별 조립 방법을 본다. **지금 CAD 위에 뜨는 안내가 바로 이것의 시안이다** |
| 실적 기록 | 누가, 언제, 몇 개를 만들었나. 토크 · 압입력 같은 측정값도 기록한다 |
| 이력 추적 | 어느 제품에 어느 로트의 부품을 썼나. 불량이 나면 역추적한다 |
| 품질 · 설비 | 검사 결과, 설비 상태, 불량 집계 |

PDM이 MES에 넘기는 **묶음**: 제조 BOM(승인된 품번 목록), 조립 순서, 단계별 작업표준(규칙에서 뽑은 값 · 주의사항 · 공구), CAD(3D). 반대로 MES는 실적과 불량 정보를 PDM에 돌려줘 설계 개선에 쓴다.

## 7. 다음 단계

1. 조립 규칙 화면: 규칙을 목록으로 보고, 어느 분류 · 공정에 걸리는지 온톨로지로 본다
2. 제품 기준 묶음: 제품 하나에 CAD · BOM · 사양서 · 규칙이 묶여 보이고, 쓰이는 부품이 연결돼 표시된다
3. MES 발행: 제조 BOM + 작업표준 묶음을 내보낸다 (형식은 MES를 정하면 확정)
4. 규칙 원본 추출: 작업표준서 PDF를 올리면 규칙 후보를 뽑아 사람이 확정한다 (사양서 올리기와 같은 흐름)
